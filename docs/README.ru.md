# vpn_specify

[English](../README.md) · [Português (Brasil)](README.pt-BR.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · **Русский** · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · [हिन्दी](README.hi.md) · [العربية](README.ar.md)

Подключает VPN **только для выбранных вами приложений**. Остальной компьютер
остаётся в обычной сети.

```
            ┌──────────────── vpn_specify ────────────────┐
 chrome ──► │ SOCKS5-прокси 127.0.0.1:10800 ┐              │
 curl   ──► │ HTTP-прокси   127.0.0.1:10801 ┴─► туннель VPN┼──► сеть VPN
            └─────────────────────────────────────────────┘
 остальной ПК ────────────────────────────────────────────────► обычный интернет
```

Никаких фоновых служб. В Windows есть два исполняемых файла из одного кода:

- `vpn_specify.exe`: графический интерфейс (без консоли).
- `vpn_specify-cli.exe`: команды терминала (`up`, `run`, `status`, `update`).

В Linux один исполняемый файл, `vpn_specify`, с графическим интерфейсом и
командами терминала (см. [Linux](#linux)).

Интерфейс, установщик и сообщения доступны на **10 языках**
(см. [Языки](#языки)).

> Это руководство пользователя. О сборке, публикации версий и структуре кода
> см. [README на английском](../README.md#building).

## Установка

Скачайте `vpn_specify-<версия>-win64.zip` со страницы
[releases](https://github.com/D3T3F/vpn_specify/releases), распакуйте и
запустите `vpn_specify-setup.exe`:

- Выберите язык вверху окна установщика; приложение будет использовать его и
  дальше (его можно сменить позже в **Настройках**).
- Папка по умолчанию: `C:\Program Files\vpn_specify` (другую можно выбрать через **Обзор…**).
- Параметры: ярлыки на рабочем столе и в меню «Пуск».
- Ничего не скачивается: программа и WinDivert уже внутри установщика.
- Повторный запуск установщика обновляет существующую установку (в той же папке).
- Удаление: Параметры > Приложения > Установленные приложения > vpn_specify.
  Вы выбираете, удалить или сохранить данные. Ярлыки, созданные приложением
  (например, `DiscordVPN`), тоже удаляются.

Без щелчков (для скриптов):

```powershell
vpn_specify-setup.exe /silent [/dir=D:\Apps] [/nodesktop] [/nostartmenu] [/lang=ru]
"C:\Program Files\vpn_specify\vpn_specify.exe" uninstall /silent [/keepdata]
```

Работает и без установки (портативный режим): достаточно папки `data\` (или
пустого файла `portable`) рядом с `vpn_specify.exe`.

## Графический интерфейс

Откройте `vpn_specify.exe`. Windows запросит права администратора.

1. **VPN > Импортировать файл…**: файл `.ovpn`/`.conf` копируется в папку
   данных. Если VPN требует входа, используйте **Учётные данные**: пароль
   хранится с помощью DPAPI, прочитать его может только ваша учётная запись
   Windows. **Изменить** позволяет переименовать VPN (приложения, которые его
   используют, следуют за ним) и изменить содержимое файла; сначала этот VPN
   нужно отключить.
2. **Приложения в VPN > Добавить приложение…**: выберите `.exe` или ярлык из
   меню «Пуск» (например, Discord). Для приложений с программой обновления
   (`Update.exe --processStart Discord.exe`) нужный процесс (`discord.exe`)
   определяется автоматически.
   - *Полный перехват* (по умолчанию): весь трафик, включая голос/UDP (WinDivert).
   - *Прокси*: только TCP, для браузеров и приложений Chromium; драйвер не нужен.
3. **Создать ярлык**: создаёт, например, `DiscordVPN` в меню «Пуск» (и, при
   желании, на рабочем столе). Он появляется в поиске Windows рядом с обычным
   Discord.

При открытии ярлыка:

- Если VPN выключен, один раз появится UAC. Окно покажет ход подключения,
  подключится, откроет приложение и закроется само.
- Если VPN уже включён, приложение откроется сразу, без UAC.
- Приложение открывается от имени обычного пользователя, а не администратора.
- Если включено «Отключать VPN, когда открытые через него приложения закрыты»
  и окно закрыто, VPN отключится примерно через 30 с после закрытия
  приложений.

### Приложения, запускаемые вместе с системой

В окне приложения (**Добавить приложение…** или **Изменить**) отметьте
**Открывать вместе с Windows**. При входе в систему vpn_specify подключает VPN
и открывает все отмеченные приложения, не показывая окно. В списке они
помечены «запускается вместе с системой».

- **Без UAC при входе**: vpn_specify создаёт задачу планировщика
  `vpn_specify\Start apps in VPN` (в «Планировщике заданий»), которая
  запускает `vpn_specify.exe autostart` через 15 с после входа, уже с правами
  администратора. Приложения открываются от имени обычного пользователя.
- В Linux параметр называется **Открывать вместе с системой**. Запись
  находится в `~/.config/autostart/vpn_specify.desktop` и выполняется через
  10 с после входа в сеанс. VPN OpenVPN в этот момент запрашивают пароль
  администратора.
- Запись одна: она создаётся при отметке первого приложения и удаляется,
  когда отмеченных не остаётся. Она обновляется при каждом запуске
  vpn_specify, поэтому следует за исполняемым файлом, если он переместился
  или обновился.
- Одновременно активен только один VPN, поэтому отмеченные приложения должны
  использовать **один и тот же VPN**. Окно предупредит, если это не так.
- Сразу после входа сеть может появиться не сразу. Каждое приложение
  пробуется до 4 раз с паузами. Отклонённый пароль или отсутствующие учётные
  данные не повторяются. То, что не удалось открыть, показывается в
  сообщении.
- Программа удаления удаляет задачу.

Одновременно активен только один VPN. Не перехватывайте общие имена вроде
`cmd.exe`: в VPN попадут все процессы с таким именем.

Папка данных (кнопка **Папка данных**): `configs\`, `settings.json`
(приложения и настройки), `language` и `vpn_specify.log`. При установке это
`%LOCALAPPDATA%\vpn_specify`, в портативном режиме — `data\` рядом с exe.

Не запускайте установленную версию и портативную копию одновременно: обе
используют одни и те же локальные порты (10799–10801).

## Поддерживаемые форматы

| Конфигурация | Как работает | Нужны права администратора? |
|---|---|---|
| **WireGuard** (`.conf`) | Туннель полностью работает внутри процесса (wireguard-go + стек TCP/IP gVisor). Сетевой адаптер не создаётся. | Нет |
| **OpenVPN** (`.ovpn`) | Использует установленный `openvpn`, но блокирует всё, что изменило бы маршрутизацию или DNS системы (redirect-gateway, маршруты, DNS, block-outside-dns). Прокси привязывает свои сокеты к туннелю — именно это направляет трафик через VPN. | Да (OpenVPN создаёт адаптер) |

Если OpenVPN нет, vpn_specify предложит установить его при подключении: в Windows он загружает официальный установщик (проверяется по зафиксированному SHA-256) и устанавливает его без вопросов и без графического интерфейса OpenVPN; в Linux устанавливает пакет `openvpn` дистрибутива (apt, dnf, yum, zypper, pacman или apk). Его можно установить и самостоятельно.

## Использование

```powershell
# 1. Подключиться (не закрывайте этот терминал; Ctrl+C отключает)
vpn_specify-cli up C:\vpns\work.ovpn

# 2. В другом терминале открыть приложения внутри VPN
vpn_specify-cli run chrome                       # отдельный Chrome, в VPN только он
vpn_specify-cli run firefox
vpn_specify-cli run msedge https://intranet.company
vpn_specify-cli run curl https://ifconfig.me
vpn_specify-cli run git clone https://git.internal/repo.git
vpn_specify-cli run powershell                   # оболочка, чьи команды используют прокси

# Подключиться и сразу открыть приложение
vpn_specify-cli up wg0.conf -- chrome

# Проверка: IP напрямую и через VPN, по TCP и UDP
vpn_specify-cli status
```

### Перехват по процессу (`-capture`): ВЕСЬ трафик приложения через VPN

Для приложений, которые игнорируют прокси или используют собственный UDP
(голос Discord, игры, нативные приложения), `-capture` перехватывает пакеты
процесса по имени исполняемого файла. В самом приложении ничего настраивать
не нужно:

```powershell
# терминал от имени администратора
vpn_specify-cli up work.ovpn -capture discord.exe
# затем откройте Discord как обычно (ярлык в меню «Пуск»)
```

- **TCP** идёт через прозрачный прокси; **UDP** (голос, видео) — через сокеты
  внутри VPN; **IPv6** процесса блокируется, чтобы приложение использовало
  IPv4 через VPN.
- Другие программы не затрагиваются, но каждый исходящий пакет проходит через
  `vpn_specify`, что в тесте стоило около 10 % скорости.
- Если приложение уже было открыто, его TCP-соединения разрываются, чтобы
  переподключиться через VPN. Надёжнее всего открывать приложение после `up`.
- Можно повторять: `-capture discord.exe -capture steam.exe`.
- Работает с WireGuard и OpenVPN.
- Имена (DNS), которые приложение разрешает через Windows, по-прежнему
  используют обычный DNS компьютера: DNS-сервер видит, *какие* домены, но
  трафик идёт через VPN.

Требования: права администратора и файлы [WinDivert 2.2.2](https://github.com/basil00/WinDivert/releases/tag/v2.2.2)
(`WinDivert.dll` и `WinDivert64.sys`, x64) в `.\windivert\` или рядом с
`.exe`. Защитник Windows часто помечает WinDivert как нежелательный, потому
что его используют и вредоносные программы; разрешите папку в «Безопасность
Windows > Исключения». Во время перехвата действует временное правило
брандмауэра «vpn_specify capture», которое удаляется при выходе.

### UDP

Есть два способа:

1. **SOCKS5 UDP** (`127.0.0.1:10800`, UDP ASSOCIATE): для приложений,
   поддерживающих UDP через SOCKS5.
2. **Перенаправление портов `-L`**: работает с **любой** программой, даже с
   теми, что не умеют работать с прокси. Локальный порт становится адресом
   внутри VPN:

```powershell
vpn_specify-cli up work.ovpn -L udp:15353=10.0.0.5:53 -L tcp:13389=internal-server:3389
# теперь: внутренний DNS на 127.0.0.1:15353 и внутренний RDP на 127.0.0.1:13389
mstsc /v:127.0.0.1:13389
```

`-L` принимает `[tcp|udp:]локальныйПорт=хост:порт` (или локальный
`ip:порт`) и может повторяться. Для UDP у каждого локального источника своя
сессия; сессии без ответа в течение 2 минут закрываются.

### Полезные параметры

- `up -v`: полный журнал (включая журнал OpenVPN).
- `up -dns 10.0.0.53`: принудительно задаёт DNS внутри VPN.
- `up -socks 127.0.0.1:20800 -http 127.0.0.1:20801`: другие порты, например для двух VPN одновременно. В `run` используйте те же порты.
- `run -profile client2 chrome`: отдельный профиль браузера (cookie, входы).
- `run -chromium <приложение Electron>`: принудительно включает флаги прокси Chromium.
- `run -detach <программа>`: не ждать завершения программы.

## Как каждое приложение попадает в VPN

- **Chrome / Edge / Brave / Vivaldi**: `--proxy-server=socks5://...`, отдельный
  профиль в `%LOCALAPPDATA%\vpn_specify\profiles\` (иначе окно открылось бы в
  уже запущенном Chrome, вне VPN), удалённый DNS и WebRTC только через прокси.
- **Firefox**: отдельный профиль с прокси SOCKS5, удалённым DNS и
  отключённым DoH.
- **Любая другая программа**: переменные `HTTP_PROXY`, `HTTPS_PROXY` и
  `ALL_PROXY`. Работает с curl, git, npm, pip, Go, .NET HttpClient и многими
  другими.

Имена (DNS) разрешаются **внутри VPN**, поэтому внутренние имена
(`intranet.company`) работают и не утекают в DNS вашей сети.

## Ограничения

- **Приложения, игнорирующие прокси**: используйте `-capture` (или `-L` для фиксированных адресов).
- Chrome и Firefox не отправляют UDP (QUIC/HTTP3) через SOCKS; они используют
  TCP, который работает нормально.
- UDP и режим OpenVPN работают только с **IPv4**.
- Если `vpn_specify` принудительно завершить, `openvpn` завершится вместе с
  ним (Job Object в Windows, SIGTERM в Linux), но маршрут с метрикой 9999
  может остаться на отключённом адаптере TAP. Он ни на что не влияет;
  обычный Ctrl+C удаляет всё.
- Прокси слушает только `127.0.0.1`, но **любая программа на вашем ПК** может
  использовать его, пока работает `up`.

## Linux

В Linux работают графический интерфейс и команды терминала (`up`, `run`,
`status`, `update` и `-L`), с WireGuard и OpenVPN, на тех же портах, что и в
Windows. Установщик и `-capture` по-прежнему есть только в Windows.

```sh
tar -xzf vpn_specify-<версия>-linux-amd64.tar.gz   # или -linux-arm64
sudo install vpn_specify-<версия>-linux-amd64/vpn_specify /usr/local/bin/
vpn_specify                                # открывает графический интерфейс
```

### Графический интерфейс в Linux

Запустите `vpn_specify` без аргументов. В первый раз используйте
**Настройки > Добавить «vpn_specify» в меню приложений**, чтобы значок
появился в меню. Окно такое же, как в Windows, со следующими отличиями:

- **Окно**: это та же страница, что и в Windows, которую отдаёт сам
  vpn_specify на `127.0.0.1` (случайный порт, защищён случайным токеном). Она
  открывается как окно приложения (без вкладок и адресной строки) в Chrome,
  Chromium, Edge, Brave или Vivaldi, с отдельным профилем. Если их нет,
  открывается вкладка в браузере по умолчанию. Работает с X11 и Wayland.
- **Без root**: интерфейс работает от имени обычного пользователя. При
  подключении VPN **OpenVPN** система запрашивает пароль администратора
  (`pkexec` из polkit) только для `openvpn`. Он работает в небольшом
  вспомогательном процессе, который завершает его при отключении или закрытии
  vpn_specify. Привязка сокетов к туннелю без root требует ядра 5.7 или
  новее. WireGuard пароль не запрашивает.
- **Добавить приложение** показывает приложения из меню приложений (файлы
  `.desktop`, включая flatpak и snap) с поиском. **Выбрать файл…**
  использует zenity или kdialog; без них введите путь в поле «Программа».
- **Только режим прокси**: полного перехвата нет. В VPN попадают браузеры,
  приложения Chromium/Electron (Discord, Slack, VS Code…) и программы,
  учитывающие `HTTP_PROXY`. Голос/UDP Discord и игры — нет.
- **Создать ярлык** записывает файл `.desktop` в
  `~/.local/share/applications/` (он появляется в поиске меню рядом с
  исходным приложением) и, если отмечено, на рабочий стол.
- **Учётные данные**: пароль шифруется (AES-GCM) ключом из
  `~/.local/share/vpn_specify/secret.key` (права 0600), который хранится
  отдельно от `settings.json`. Он защищён правами доступа к файлу, как ключ
  SSH, а не системной связкой ключей. Пароли, сохранённые в Windows (DPAPI),
  нужно ввести заново.
- **Данные**: `~/.config/vpn_specify/` (`configs/`, `settings.json`,
  `language`, `vpn_specify.log`).

Жизненный цикл такой же, как в Windows. При открытии ярлыка с выключенным VPN
окно показывает ход подключения, подключается, открывает приложение и
закрывается. При закрытом окне VPN отключается примерно через 30 с после
закрытия открытых через него приложений.

### Терминал в Linux

```sh
vpn_specify up wg0.conf                    # WireGuard: без root
sudo vpn_specify up work.ovpn              # OpenVPN: нужен root и пакет openvpn

# в другом терминале, от имени обычного пользователя
vpn_specify run chrome                     # находит google-chrome-stable, chromium...
vpn_specify run firefox
vpn_specify run curl https://ifconfig.me
vpn_specify status
```

Отличия от Windows:

- **OpenVPN**: в Linux привязки сокета к IP туннеля недостаточно, чтобы он
  выходил через туннель. Поэтому прокси привязывает свои сокеты к интерфейсу
  `tun` через `SO_BINDTODEVICE` и переводит `rp_filter` этого интерфейса в
  режим *loose*. Без этого дистрибутивы со строгим `rp_filter` (Fedora, RHEL)
  отбрасывали бы ответы. Маршруты и DNS системы не меняются, как и в Windows.
  Если `vpn_specify` принудительно завершить, `openvpn` получит SIGTERM и
  тоже завершится.
- **`sudo vpn_specify up ... -- программа`**: программа открывается от имени
  того, кто вызвал `sudo`, а не от root. Профиль браузера создаётся в
  домашней папке этого пользователя. Но проще всего запускать `run` в другом
  терминале без `sudo`.
- **Профили браузеров**: в `~/.config/vpn_specify/profiles/`. Firefox и
  Chromium, установленные как snap (по умолчанию в Ubuntu), не могут читать
  скрытые папки в домашнем каталоге, поэтому для них профиль хранится в
  `~/snap/<app>/common/vpn_specify/profiles/`.
- **Приложения, игнорирующие прокси**: без `-capture` используйте `-L` для
  фиксированных адресов.

## Android

Установите `vpn_specify-<версия>-android-arm64.apk` (Android 8 или новее; при запросе
разрешите установку из этого источника). В Android есть встроенная VPN для отдельных
приложений, поэтому прокси не используется: весь трафик TCP и UDP выбранных приложений,
включая голос, идёт через туннель, без root. Остальной телефон остаётся в обычной сети.

1. **Импортировать файл…**: выберите `.conf` WireGuard или `.ovpn` OpenVPN.
2. **Выбрать приложения…**: отметьте приложения, использующие VPN, например Discord.
3. **Подключить**, и в первый раз примите разрешение VPN в Android.

Android не может определить, что приложение открыто, поэтому есть два способа:

- **Оставить VPN включённой** (рекомендуется): приложение всегда в VPN, как бы его ни
  открыли, а больше ничего в ней нет. **Подключаться при запуске телефона** делает это
  при каждом запуске. В системных настройках VPN **Постоянная VPN** заставляет Android
  перезапускать её автоматически, а **Блокировать соединения без VPN** не даёт выбранным
  приложениям выходить в сеть в обход неё (это блокирует и остальной телефон).
- **Ярлык**: создаёт на главном экране значок «Discord (VPN)», который подключается и
  затем открывает приложение. Обычный значок VPN не включает.

Ограничения на Android:

- Выбранное приложение никогда не выходит в сеть в обход VPN. Если VPN даёт доступ только к внутренней сети, сайты в интернете в этом приложении не откроются.
- OpenVPN: сертификаты и ключи должны быть внутри `.ovpn`, TAP не поддерживается, закрытый ключ с паролем пока тоже. Директивы, запускающие программы, удаляются.
- Android держит активной одну VPN: запуск другой отключает эту.
- Изменение приложений или VPN во время подключения пересоздаёт туннель, что ненадолго
  прерывает работу выбранных приложений.

Язык следует за системой, его можно изменить в **Настройках**. Приложение ищет новые
версии на GitHub, а Android просит подтвердить каждое обновление.

## Обновления

При открытии интерфейса vpn_specify проверяет последнюю версию в
[выпусках на GitHub](https://github.com/D3T3F/vpn_specify/releases). Если
есть более новая, вверху окна появляется уведомление:

- **Обновить**: скачивает пакет, проверяет SHA-256, отключается, закрывается,
  устанавливает и снова открывается уже в новой версии.
- **Не сейчас**: скрывает уведомление до следующего запуска.
- **Пропустить эту версию**: больше не уведомлять об этой версии, только о
  следующей.
- **Что нового**: показывает текст выпуска.

В **Настройках** можно отключить проверку при запуске и проверить сразу
(**Проверить обновления**). В терминале:

```sh
vpn_specify update           # показывает новую версию и спрашивает, установить ли её
vpn_specify update -check    # только проверяет
vpn_specify update -y        # устанавливает без вопросов
vpn_specify version
```

Как устанавливается новая версия:

- **Windows, установленная версия**: `vpn_specify-setup.exe` из выпуска
  запускается в режиме обновления. Он использует ту же папку, сохраняет
  существующие ярлыки и при необходимости запрашивает UAC.
- **Windows, портативная версия**: тот же установщик только заменяет файлы
  папки, без записей в реестре и ярлыков.
- **Linux**: исполняемый файл заменяется на месте. Если папка требует root
  (например, `/usr/local/bin`), система запрашивает пароль (`pkexec`). Перед
  заменой vpn_specify проверяет, что новый файл запускается и сообщает
  правильную версию.

Безопасность: загрузка принимается только с
`github.com/D3T3F/vpn_specify/releases/download/` и только если её SHA-256
совпадает со значением, которое GitHub указывает для файла (или с файлом
`SHA256SUMS` в выпуске). Без хеша ничего не устанавливается. Это защищает от
повреждённой или подменённой по дороге загрузки, но не от того, у кого есть
доступ к учётной записи GitHub; для этого пакеты нужно подписывать. Сборки
без версии (`dev`) никогда не проверяют обновления.

## Языки

Интерфейс, установщик, сообщения и справка терминала доступны на: English,
Português (Brasil), Español, Français, Deutsch, Русский, 简体中文, 日本語,
हिन्दी и العربية (с раскладкой справа налево).

- **По умолчанию**: язык системы, если он есть в этом списке (язык
  интерфейса Windows; в Linux — `LANGUAGE`, `LC_ALL`, `LC_MESSAGES` или
  `LANG`), иначе английский.
- **Выбор**: вверху установщика Windows или позже в **Настройки > Язык**
  (окно переключается сразу). Выбор сохраняется в папке данных (файл
  `language`) и действует и для команд терминала. Тихая установка принимает
  `/lang=<код>`.
- Технические журналы и справка по отдельным параметрам терминала остаются
  на английском.

Хотите улучшить перевод или добавить язык? См.
[Adding or improving a translation](../README.md#adding-or-improving-a-translation).
